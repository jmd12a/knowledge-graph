# 缩短导入与删除发布窗口 - Plan

## Summary

导入和删除按存储并行应用同一份差量计划。删除在跨库核验和文档状态提交后恢复查询，原文及检查点随后清理。查询持锁范围和重建、重索引流程沿用当前设计。

## Problem Frame

正式写入期间按知识库阻止查询。现有发布先后写入 Qdrant、PostgreSQL 和 Neo4j，删除还在门禁内等待原文及检查点清理。相关入口为 `MutationApplier.apply`、`Metadata.finish` 和 `Worker.execute`。

## Goal Capsule

**Objective** 在保持跨存储查询一致性的前提下，减少导入和删除的停读时间。

**Acceptance** 差量写入重叠。全部写入和核验成功后才可查询。清理暂停、失败或重启时，查询读到已经提交的删除结果，任务等待清理完成才成功。

## Product Contract

- R1. 每个知识库的正式写入仍使用现有门禁、排队顺序和不可变计划。半写入或核验失败按原计划修复，修复前继续阻止查询。
- R2. 删除的可见性在核验通过后提交。原文件或检查点清理期间可查询，下载已删除原文返回原有的 404。
- R3. 删除任务成功仍表示计划要求的清理已完成。清理失败可重试，重启或重试只执行清理，结果及错误通过现有任务入口查看。
- R4. 清理中的删除保留同库队头。其他知识库可以继续查询和准备。单正式写入 Worker 在一次清理结束或进入退避后才执行其他任务。同库后续任务在清理完成后继续。
- R5. 工作范围为导入、删除的发布与清理。沿用现有查询锁和重索引、整库重建行为。

## Planning Contract

- KTD1. 差量计划验证及 Qdrant 集合就绪后，启动 Qdrant、PostgreSQL、Neo4j 三个分支。每个分支保留自身的删除/写入顺序。使用等待所有分支结果的方式汇合，即使一个分支报错也等待其他已发起分支结束。外层任务取消时保留分支执行，在排他锁内排空后再传播取消。只有全部成功才进入现有核验，分支不分别更新任务进度。全量路径保留原写入顺序。
- KTD2. 保持现有局部核验和跨库引用校验。Neo4j 关系端点、同组关系、来源贡献、向量归属和证据仍以原计划为准。
- KTD3. PostgreSQL 在同一事务内将删除文档标为不可见、取消被撤回来源的任务或计划引用、设置知识库为 `READY`，并把本次删除置为 `CLEANING`。事务保留当前删除的 `plan_path`，保存成功计数和告警。无清理目标时沿用直接成功。确认提交或回读到已发布状态后，退出排他锁。
- KTD4. `CLEANING` 路径只读取本次已登记的计划并按既有文件适配器逐个清理。第一次在发布调用释放锁后立即执行，`worker --once` 仍能完成正常删除。独立清理尝试从 1 开始，后续自动重试使用现有退避和三次上限。最后一次失败或重启发现最后一次清理中断时登记 `CLEANUP_FAILED`，显式 retry 将同一任务重新置为 `CLEANING`。两种状态均只占写队头，均不进入正式写入修复或关闭读门禁。领取时跳过已删除文档的幂等短路，并裁决已用尽尝试的中断清理。新幂等键的重复删除等待原清理结束。清理完成后使用持久化结果标记任务成功。清理目标均允许重放。
- KTD5. 逻辑提交与清理提交若丢失响应，按持久化任务状态裁决。若数据库暂时不可读，保留当前记录交由下次领取裁决。旧清理引用和 MinIO 对迟到写入的封存机制沿用现有语义。本次删除自己的计划在待清理期间继续受任务状态保护。

## Implementation Units

### U1. 并行应用导入和删除的差量

范围为 `src/knowledge_graph/services/construction/apply.py`。复用现有适配器、原计划和核验，保留全量写入顺序。覆盖 R1、R5。

### U2. 独立完成已发布删除的清理

范围为 `src/knowledge_graph/adapters/metadata/postgres.py`、`src/knowledge_graph/ports/metadata.py`、`src/knowledge_graph/domain/jobs.py`、`src/knowledge_graph/worker.py`、`src/knowledge_graph/services/construction/apply.py`，以及相关设计和运行说明。复用 `jobs` 状态及计划字段和现有重试入口，保持 SQL 表结构。覆盖 R2 至 R5。

## Verification Contract

- 用受控失败验证一个并行分支失败时，其他分支结束前不会进入核验或完成，半写入保持门禁并按原计划恢复。
- 用实际发布路径暂停或阻断原文件清理，检查知识库已恢复查询，已删除资料不能下载，删除任务仍未成功。
- 验证清理重试、最后一次清理中断后重启及明确重试，核对图和向量不会重放，同库后续任务仍遵守队头，最终原文和关联材料已回收。
- 运行现有隔离的 Worker/存储联调和相关检查。故障模拟采用已有评测方式，针对现有覆盖缺口扩充。

## Definition of Done

两项改动都走现有 Worker 入口，完成针对性验证。设计说明对应实际的门禁、状态和重试语义。
