# 模型服务与数据集调研

本文区分当前已使用的模型与资料，以及仅完成初筛的候选。公开资料入口来自 2026-10-31 的调研记录；模型名称、调用配置和实际验证范围以项目运行记录为准。启动配置见[运行指南](运行指南.md)，结果与未完成项见[评测说明与结果](评测说明与结果.md)。

## 1. 当前模型与配置边界

| 用途 | 当前实测配置 | 说明 |
|---|---|---|
| 构建抽取、规则整理及描述生成 | `qwen3.7-plus` | 通过百炼 OpenAI 兼容端点调用 |
| 在线检索规划 | `qwen3.7-plus` | 输出受约束计划，由程序校验后执行 |
| 文档与问题向量化 | `qwen3.7-text-embedding`，1024 维 | 图对象与文档切片索引使用兼容配置 |

在线检索读取 `llm` 配置。可选 `construction_llm` 为构建提供完整独立 profile；未配置时复用 `llm`。独立 profile 包含各自模型、端点、预算和凭据环境变量名称，不能理解为只覆盖模型名称的部分配置。两条链路共享 Embedding 配置与存储端口。

模型适配需要区分请求格式与结果校验。项目已验证 schema 约束下的结构化结果校验和 `json_object` 请求链路；供应商严格 `json_schema` 路径及真实格式纠正分支尚未实测。代码中有相应分支，不能代替真实调用证据。

1024 维是当前已经运行的配置，不代表对所有语料最优。更换 Embedding 模型或参数时应检查索引兼容性，并按维护流程重建。相同维度的不同模型向量不能直接混用。

轻量分类、查询改写和独立 Rerank 服务曾作为候选用途。当前记录不据此宣称它们已经接入，也不把候选模型的接口说明当作项目效果验证。

## 2. 已使用资料及其证明范围

| 资料 | 当前用途 | 能证明什么 | 不能据此推断什么 |
|---|---|---|---|
| 人工构造的服务目录、关系及边界样例 | 确定性机制、维护恢复与专项边界检查 | 身份、来源、预算、串行维护和恢复等机制在指定条件下的行为 | 企业自然语言抽取准确率、真实业务覆盖率 |
| CUAD 中两份完整短合同 | 真实模型构建、合同规则检索与语义复核 | 当前模型和流程在这两份真实合同上的结果与缺口 | 已跑完整 CUAD、已完成合同业务验收或获得全量基准分数 |

CUAD 提供商业合同与专家条款标注。原调研记录为 510 份合同、41 类条款、超过 1.3 万个专家标注。它适合检查主体、日期、期限、条款与原文溯源，但没有直接提供本项目所需的完整合同本体和关系图；关系、适用条件及规则完整性还需要独立核验。[CUAD 官方介绍](https://www.atticusprojectai.org/cuad/)

两份合同是有限样本。机制检查通过、真实调用完成与人工语义验收是不同证据，不能相互替代。当前合同语义与全文召回仍有未完成项，完整结果和后续定向回归见[评测说明与结果](评测说明与结果.md)。

## 3. 未运行的候选数据集

下列资料完成过适用性初筛，未作为本项目已经运行的基准。表中规模来自原调研资料，不代表已下载或处理相应全集。

| 候选 | 资料与标注 | 适合检查的环节 | 适用限制 |
|---|---|---|---|
| [DABstep](https://huggingface.co/datasets/adyen/DABstep) | 支付规则手册、商户资料、交易 CSV、费率 JSON 与分析任务；主集 450 题答案隐藏，公开开发集 10 题带答案 | 规则与结构化数据关联、适用条件、费用来源解释 | 数据为合成；不提供构建所需的标准业务本体，分析任务也包含外部计算职责 |
| [TAT-QA](https://nextplusplus.github.io/TAT-QA/) | 2,757 组财报表格与文本、16,552 个问题，含推导和数量级 | 实体、期间、单位、表格事实与计算依据 | 原任务给定相关上下文；改为全库检索需说明新设置 |
| [BIRD Mini-Dev](https://github.com/bird-bench/mini_dev) | 数据库、字段说明、业务知识提示、问题与参考 SQL | 术语到字段映射、关联及问数依据 | 偏结构化数据；长文档与独立本体需补充，使用时需固定修订版本 |
| [FinanceBench](https://github.com/patronus-ai/financebench) | 财报 PDF、公司与期间元数据、答案及页级证据；公开 150 题 | 长文档解析、实体期间归一与证据检索 | 无完整实体关系标注；公开部分不等于全部 10,231 题 |
| [Re-DocRED](https://github.com/tonytan48/Re-DocRED) | 4,053 篇文档的修订关系标注 | 文档级实体关系抽取回归 | 主要为百科语料，不能直接替代企业业务建模验证 |

DABstep 的[原始资料目录](https://huggingface.co/datasets/adyen/DABstep/tree/main/data/context)和[数据与评测说明](https://huggingface.co/blog/dabstep)可用于后续设计支付场景。商户、交易、支付网络和费率规则是可考虑的建模对象，不是数据集原生提供的本体金标准。若用于本项目，应分别检查知识底座提供的定义与证据，以及外部 Agent 执行的计算。

原调研还记录了部分公开采用案例：CUAD 与 TAT-QA 进入 [RAGBench](https://huggingface.co/datasets/galileo-ai/ragbench)，DABstep 用于 [DS-STAR](https://research.google/blog/ds-star-a-state-of-the-art-versatile-data-science-agent/)，FinanceBench 用于 [NVIDIA RAG Blueprint](https://docs.nvidia.com/rag/latest/accuracy-benchmarks.html)，BIRD 有 [Ask RITA](https://cvs-health.github.io/AskRITA/benchmarks/guide/) 接入记录。这些案例说明任务用途，不构成本项目已经运行对应评测的证据。

## 4. 后续选材与验证原则

新增资料应先确定业务模型、资料范围和可核验问题，再决定是否扩展解析器或数据映射。候选语料主要为英文；当前两份合同的结果不能直接推广到中文企业资料、复杂表格或扫描 PDF。

评测需要分别记录实体与关系抽取、身份对齐、规则完整性、证据支持、检索覆盖、删除重建和中断恢复。涉及统计任务时，还要区分知识服务返回的口径与外部程序执行的计算。公开数据集名称、少量样本验证和完整基准成绩应分别表述。

项目的职责与存储约定见[架构设计](../02-项目设计/架构设计.md)和[实施设计](../02-项目设计/实施设计.md)。
