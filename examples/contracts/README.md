# 公开合同业务模型

`model.yaml` 用于 `evals/corpus/cuad/` 的两份公开合同及 `evals/corpus/cuad-long/` 的完整长合同。Party 的精确原文名称和 Agreement 的原文标题采用来源内身份，不授权近似拼写或跨文件合并。

Clause 优先以原文 heading（含编号和标题文字）作为身份，完整正文保存在 definition，避免长正文超过身份索引预算；没有独立标题或标题重复时使用具有区分度的条款开头原文，不编造标题。既有知识库保留原模型，新模型用于新建知识库。`full_statement` 原子组保存实际摘录及证据；程序检查字段、原文引用和输入授权，不用整块上下文的引用或模型完整性标记否决条款。全部定义、条件、例外和适用范围保存在同一原文定义里；模型不要求抽取器制造源文没有的 exceptions 字段。无法确定完整性或指代时保留条款及模型标记，不将未知状态改写成完整或已解析。

固定检查和人工结论只留在 evals 侧，不放入待抽取原文或本模型的样例答案。程序只验证知识保存与证据，不计算费用或作法律判断。

`openrouter-quality.yaml` 是可选质量配置：GLM 5.3 负责抽取、规划和候选重排，Gemini Embedding 2 生成 3072 维向量，凭据从 `OPENROUTER_API_KEY` 读取。它用于新知识库；既有知识库的向量模型不能直接替换，须显式重建索引。检索仍返回调用方请求的 Top K，只扩大内部候选池并重排；模型重排失败保留原始排序并标记降级。证据修复仅针对实际失败的候选进行一次，修复仍须满足原文证据与身份约束。

使用时，将 `openrouter-quality.yaml` 的 `llm`、`construction_llm`、`embedding` 及检索设置合并到本机 `configs/app.local.yaml`，保留原数据库连接和数据目录。在本机 `.env` 设置 `OPENROUTER_API_KEY`，启动 API、Worker 时共同使用该配置。密钥和本机配置不纳入版本控制。
